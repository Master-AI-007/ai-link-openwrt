## 1. 项目概述与核心定位

**AI-LINK (`ai-link-openwrt`)** 是专为现代 OpenWrt（`fw4` / `nftables`）打造的下一代全栈智能透明代理、异地组网回家（HomeLink）与 DNS 净网护盾系统。它将高性能 `sing-box` 内核、内核态 `nftables` 硬件级国内分流、**“永不断连”的 1~5 组优先级自动节点池与智能分流卡片引擎**、多协议免证书回家服务以及全息 3D 可视化交互面板融为一体。

### 为什么需要重新设计一款 OpenWrt 代理插件？

长期以来，OpenWrt 用户在使用传统透明代理插件（如 OpenClash、PassWall、ShadowSocksR Plus+、HomeProxy 等）时，普遍面临四大痛点：

1. **频繁跳点导致长连接中断**：传统插件依赖内核原生 `urltest`，只要某个备选节点瞬时延迟低几毫秒就立即切换出口，导致正在使用的 ChatGPT 对话报错 `network error`、Claude/Gemini 触发异地 IP 风控掉登录、海外游戏掉线、SSH 终端断开。
2. **“假活节点”黑洞与死节点粘滞问题**：许多机场节点虽然 TCP/TLS 握手能通（普通 ping 显示绿色），但出口已被目标网站封禁、CDN TLS 握手卡死或无实际返回字节，传统测速无法识别；或者当某个自定义分流卡片绑定的节点挂掉后，传统插件不会自动逃生，导致该业务彻底断网。
3. **单臂旁路由国内断流与 IPv6 抢答漏网**：在单臂旁路由（同网段网关指向旁路由）场景下，国内直连流量因来回路径不对称触发内核防火墙丢弃（表现为微信图片发不出、国内网页偶发连接重置 RST）；开启 IPv6 后，海外网站又经常通过主路由原生 IPv6 抢先直连导致代理解析失效。
4. **配置繁琐与卸载残留**：传统插件动辄数十个生涩参数页，小白用户无从下手；而停用或卸载后往往在系统中残留策略路由（`ip rule`）、虚拟网段路由（`fc00::/18`）、内核参数修改及 `dnsmasq` 劫持配置，甚至引发卸载后全网断网。

**AI-LINK v1.0.0 正式版**围绕以下四大工程准则给出彻底解法：

- **准则一：节点永不断连（稳定压倒一切 · 默认不断不切 + 毫秒级瀑布流热备容灾）** —— 当前工作节点只要未判定为真实死亡（`dead`），绝不因其他节点微小的延迟波动而主动中断切换；一旦当前节点发生真实故障，无需重启内核或等待全量测速，立即从已预热的 1~5 组优先级自动节点池或同国健康池中以 `< 10ms` 内存态原子操作无缝接管。
- **准则二：国内流量硬件级零损耗直连** —— 大陆 IPv4/IPv6 集合（`@cn_ip4` / `@cn_ip6`）直接在 `nftables` 内核层放行并自动挂载对称 NAT 保护，不进入 `sing-box` 用户态进程，跑满千兆/万兆宽带且彻底根治单臂旁路由国内断网。
- **准则三：回家与科学上网一体化** —— 无需额外部署 WireGuard/Tailscale/FRP，内置一键创建 `VLESS-Reality`（免证书零暴露）与 `Hysteria2-TLS`（自动绑定 SHA256 指纹）回家节点，每个回家节点可独立设置访问权限并实时监控在线会话。
- **准则四：100% 可逆的零残留生命周期** —— 从启动、暂停直连、备份恢复、恢复出厂到完全卸载，每一项路由、防火墙规则、内核 `sysctl` 参数与 DNS 配置均严格对称回收，通过 `residue_scan.py` 0 残留与 `state_hash.py` 17/17 字节级状态一致性认证。

### 2.2 三大主流网络拓扑配置方案

无论您是将 OpenWrt 作为家里的唯一主路由，还是配合光猫/硬路由做“单臂旁路由”，均可按以下对应方案配置：

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 拓扑 A：主路由模式（最简单、推荐新装用户）                               │
│                                                                         │
│  [光猫桥接/路由] ──(WAN)──> [OpenWrt + AI-LINK (主路由)] ──(LAN)──> 终端 │
│                             • 无需额外网关设置，全屋设备自动透明分流     │
│                             • 外网端口映射直接在主路由生效，回家节点直通 │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│ 拓扑 B：单臂旁路由模式（主路由保留硬路由，OpenWrt 仅插 LAN 口做网关）    │
│                                                                         │
│  [光猫] ──> [硬路由主路由 192.168.1.1] <──(同网段 LAN)──> [AI-LINK 旁路] │
│                      │                                   (192.168.1.2)  │
│                      └──────────> [全屋电脑 / 手机 / NAS]                │
│                                   (网关与 DNS 指向 192.168.1.2)          │
└─────────────────────────────────────────────────────────────────────────┘
```

#### 方案一：主路由模式配置要点（零门槛）
1. OpenWrt 正常拨号（PPPoE）或从上级光猫获取 WAN 口 IP，局域网设备通过 DHCP 自动获取 OpenWrt 的 IP 作为网关和 DNS。
2. 安装 AI-LINK 后直接打开 `http://<OpenWrt_IP>:9099`，导入机场订阅并开启服务即可。
3. **推荐开关组合**：
   - **国内流量不进内核（硬件级旁路）**：`开启`（大幅降低 CPU 占用）。
   - **IPv6 智能双栈架构与代理接管**：默认 `关闭`（即处于**智能双栈分流模式**，国内走原生 IPv6 满速直连，海外精准抑制 AAAA 防漏网）。

#### 方案二：单臂旁路由模式防断网与防漏网标准配置（重点！）
在单臂旁路由架构下，主路由（如 `192.168.1.1`）与 AI-LINK 旁路由（如 `192.168.1.2`）接在同一个局域网交换机下，终端设备将网关和 DNS 指向 `192.168.1.2`。

- **第一步：旁路由 OpenWrt 接口设置**
  - 进入 OpenWrt `网络 -> 接口 -> LAN`：
    - IPv4 地址设为 `192.168.1.2`，网关填主路由 `192.168.1.1`，自定义的 DNS 服务器填 `192.168.1.1` 或 `223.5.5.5`。
    - 在 LAN 口的 DHCP 服务器中勾选 **“忽略此接口”**（由主路由统一负责 DHCP，或者在主路由 DHCP 中将默认网关与 DNS 下发为 `192.168.1.2`）。
- **第二步：为什么其它插件在旁路由下经常国内断流，而 AI-LINK 不会？**
  - 在同网段单臂旁路由下，终端访问国内网站时：`终端 -> 旁路由(192.168.1.2) -> 主路由(192.168.1.1)`，而主路由收到回包后会直接通过二层交换机发回给终端，导致旁路由的 `conntrack` 状态机只看到 SYN 看不到 SYN-ACK，在 30 秒后将连接作为无效半开连接丢弃（表现为微信图片加载失败、淘宝网页卡死）。
  - **AI-LINK 内置三大单臂旁路防断网护栏**（开启“国内流量不进内核”时自动生效，**无需手动改防火墙脚本**）：
    1. 在 `table inet ai_link` 自动挂载 `chain srcnat { type nat hook postrouting priority srcnat; }`，对 `iifname "br-lan" oifname "br-lan"` 的硬件直连流量执行动态对称 `masquerade`；
    2. 在 `prerouting` 最顶端挂载 `ct state invalid,untracked tcp flags & (syn|rst) == 0 accept` 无状态存量连接放行护栏；
    3. 自动保存并开启 `net.netfilter.nf_conntrack_tcp_be_liberal = 1`（停止或卸载时自动恢复原值），彻底消除非对称路由下的 TCP 窗口越界 RST。
- **第三步：单臂旁路由下的 IPv6 配置建议**
  - 旁路由 LAN 口的 IPv6 设置中，将路由通告服务（RA）、DHCPv6 服务、NDP 代理全部设为 **“已禁用”**（避免与主路由抢发 RA 导致局域网设备断网）。
  - 在 AI-LINK 面板 **“连接与设置 -> IPv6 智能双栈架构与代理接管”** 中保持默认的 **“关闭（智能双栈分流模式）”**：此时国内网站（B站、PT 站、内网 IPv6 NAS）正常返回真实 `AAAA` 记录走主路由原生 IPv6 直连；而命中海外代理规则的域名由 AI-LINK 自动拦截 `AAAA` 查询并分配 IPv4 FakeIP（`198.18.0.0/15`），强制走旁路由 IPv4 透明代理隧道出网，彻底杜绝海外流量从主路由 IPv6 抢答漏网！

### 4.1 传统代理插件的五大“断连与折腾”顽疾

在传统代理插件中，用户之所以觉得“代理总是不稳、隔三差五就要进后台手动切节点”，根源在于传统自动选点机制存在以下 **五大架构缺陷**：

1. **麻烦一：“唯延迟论”引发的乒乓跳点（Ping-Pong Flapping）导致长连接必断**
   - 传统插件的 `url-test` 逻辑极其简单粗暴：每隔 180 秒对组内所有节点测一次延迟，谁数字小就切谁。
   - **真实灾难场景**：您正在用 `香港-01 (32ms)` 与 ChatGPT 进行长代码生成，或正在打海外游戏、挂着 SSH 终端。此时后台测速发现 `香港-02` 瞬时延迟为 `26ms`（僅快了 6 毫秒），传统插件立刻将出口切换到 `香港-02`。由于公网出口 IP 瞬间改变，远端服务器立刻判定连接异常或会话劫持——**ChatGPT 直接弹出红色 `network error`、Claude 触发风控封号、SSH 当场卡死、游戏人物瞬移掉线**。更糟的是，3 分钟后 `香港-01` 又比 `香港-02` 快了 4ms，它又切回来，如此周而复始。
2. **麻烦二：“假活节点（TCP 通但 HTTP 无正文 / 403 封锁 / CDN 握手死锁）”黑洞**
   - 机场节点经常出现“中转入口存活，但落地出口已欠费断网、被目标网站封锁（返回 403 Forbidden / Cloudflare 质询页），或者拉取 Google Play / YouTube 大流量 CDN (`gvt1.com` / `dl.google.com`) 时 TLS 握手卡死”的情况。
   - 传统插件仅靠 TCP Ping 或极简 HEAD 请求测速，这些“半死假活”节点往往因为中转机直接秒回错误包而显得“延迟极低（比如 15ms）”，结果被 `url-test` 优先选为第一出口，导致全屋设备陷入“面板显示全绿、实际网页一个都打不开”的黑洞。
3. **麻烦三：单次偶发丢包引发的“误杀雪崩”**
   - 无线网络或跨国链路偶发 1 个 UDP/TCP 包超时是完全正常的物理现象。传统插件一旦单次探测超时就立刻判定节点死亡并强制切换，反而把原本稳定的专线切到了备用劣质线上。
4. **麻烦四：全量测速风暴（Probe Storm）耗光机场流量、触发机场审计封禁**
   - 许多用户导入 2~3 个机场订阅，合计多达 300~800 个节点。传统插件每隔几分钟就对数百个节点同时发起 HTTP 测速，一天下来光测速就白白跑掉几个 GB 的高价专线流量，甚至因为瞬间并发成百上千个连接被机场后台判定为 DDOS/爬虫滥用而直接封停订阅。
5. **麻烦五：固定分流卡片“死节点粘滞”与“随机地区节点乱入”**
   - 在传统插件中，如果您把某个自定义分流组（比如“办公专线”或“AI 专属”）绑定到了某个具体节点 `SG-Node-3`，一旦 `SG-Node-3` 挂掉，该分流组就会一直死守在坏节点上直至您手动进后台修改。
   - 此外，机场订阅里常带有 `⚡高速自动`、`🌍地区随机`、`🔄负载均衡` 等动态轮询节点，传统按名称匹配经常把它们混进业务池，导致要求固定美日 IP 的 AI 服务瞬间跳到香港或俄罗斯 IP 而无法使用。

#### 底层实现逻辑逐层拆解（为什么能做到真正意义上的“永不断连”？）：

##### 1. 粘性状态锁（Sticky Active Node Lock）—— 正常使用时“零跳点、零中断”
在 `ai-link-daemon.py` 的 `evaluate_single_auto_node()`（第 `3622~3654` 行）中，系统对当前工作组 `target_group_idx` 内的候选节点按有效延迟排序得到 `g_nodes`（首位 `fastest = g_nodes[0]`），但**并不会直接把出口设为 `fastest`**，而是先查找当前正在使用的节点 `cur_in_group`：
- **核心判定逻辑**：
  ```python
  smart_en = bool(an.get("smart_switch_enabled", False))  # 默认 False（🔒不断不切）
  if cur_in_group is not None:
      if not cur_in_group.get("cdn_tls_ok", True) and fastest.get("cdn_tls_ok", True):
          chosen = fastest  # 仅当当前节点 CDN 握手异常时才切换
      elif cur_in_group.get("is_random_region") and not fastest.get("is_random_region") and int(fastest["delay_ms"]) <= int(int(cur_in_group["delay_ms"]) * 1.28):
          chosen = fastest  # 若当前误停留在“地区随机”节点，自动替换为固定地区专线
      elif not smart_en:
          chosen = cur_in_group  # 【核心铁律】默认“不断不切”：只要当前节点活着，死锁原节点，绝不跳点！
  ```
- **带来的实际体验**：只要您当前正在用的节点没有真正挂掉，无论机场其他节点的延迟怎么上下波动，您的出口 IP 都稳如泰山。ChatGPT 连续对话几小时、SSH 挂机一整天、大文件跨国下载、海外会议永远不会因为“插件自作聪明切了个快 5ms 的节点”而掉线！

##### 2. 1~5 组瀑布流分级容灾 + 双组去重热备 —— 节点真挂时“零等待、秒级瞬移”
很多用户会问：*“如果当前节点真的被墙了或者机场某条专线断了，怎么保证不断网？”*
- **分级热备（1~5 组瀑布流）**：一个自动节点池最多可配置 5 个优先级组（`组1·主力` -> `组2·备选1` -> `组3·备选2` -> `组4·备选3` -> `组5·备选4`）。
  - 当 `组1` 中正在工作的节点 A 突然断线时，因为 `组1` 内的其他节点（如节点 B、C）在后台已经处于热备探测状态，系统无需等待临时测速，**0 等待直接切到 `组1` 内紧随其后的存活节点 B**；
  - 如果整个 `组1`（例如某机场的香港 IEPL 专线机房整体维护）全军覆没，系统在同一轮评估中自动向下瀑布式滑落至 `组2·备选1`（例如另一家机场或新加坡 CN2 节点组）中已热备好的最优节点！
  - 甚至在极端情况下（5 个分组全部不可达），系统也会自动将 `current_node` 安全降级为 `direct`（直连兜底）并点亮 `all_groups_dead_alert` 告警，防止整个内核卡死。
- **双组去重探测（Dual-Group Deduplicated Probing）**：
  - 为什么切换能做到 0 等待，同时又不浪费流量？因为后台探测引擎只对 **`当前工作组 ∪ 组1（主力组）`** 发包探测（若当前就在组 1 工作，则全池只测组 1 这最多 10 个节点；若降级到了组 2 工作，则同时测组 2 和组 1，且跨组同名节点自动去重只发 1 次请求）。组 3、组 4、组 5 以及池外几百个节点在平时 **0 探测流量**，只有当前面组全部挂掉时才按需激活。

##### 3. 主力组迟滞防抖回切状态机（Primary Group Hysteresis Revert）—— 杜绝“刚切回主力又断”的反复横跳
当 `组1（主力组）` 因故障降级到 `组2（备选组）` 后，如果 `组1` 的线路正在抢修、处于“通一下又断一下”的不稳定状态，普通插件一旦看到 `组1` 通了 1 次就立刻切回去，几秒后又断线。
- **AI-LINK 的防震荡回切实现**（`ai-link-daemon.py:3533~3559`）：
  1. 当 `cur_group_idx > 1`（当前在备选组工作）且检测到 `cand_group_idx == 1`（主力组重新出现 `ok` 节点）时，系统**不会立即回切**，而是将状态置为 `revert_pending = True`（回切观察态），并将连续恢复计数 `primary_recover_streak` 加 1；
  2. 只有当主力组**连续 `revert_confirm_count` 次（默认连续 2 次）** 探测均稳定通过 L7 检验，且距离上次回切已满冷却时间 `revert_cooldown_s`（默认 600 秒）时，才正式将工作组切回 `组1`（或者当备选组自身也挂掉、或用户手动点击面板上的 **`⏫ 立即回切`** 按钮时立即回切）；
  3. 如果在观察期内主力组又有一次探测失败，`primary_recover_streak` 立即清零重计，继续稳稳留在备选组工作。

##### 4. L4+L7 双阶体检 + Google CDN 双目标双次确认 + 抗随机节点自愈 —— 既不放进一个假活节点，也不误杀一个好节点
- **防误杀机制（`_verify_node_cdn_dual_target`，第 `2387` 行）**：
  为了识别那些“能连上但跑不动大流量 TLS”的假活节点，同时避免因为单次网络抖动误杀正常工作的节点，AI-LINK 采用 **双目标 + 连续两次失败确认（Dual-Target Dual-Fail Confirmation）**：
  - 第一主探针：`https://dl.google.com/android/repository/repository2-3.xml`（验证真实 HTTPS 200 载荷吞吐）；
  - 第二见证探针：`https://play.google.com/generate_204`（验证 Google 全球边缘 204 响应）。
  - **判定准则**：只要两个探针中有任意一个通，节点即判定为健康（`cdn_tls_ok = True`，且自动将历史 `fail_streak` 归零恢复）；**只有两个探针同时失败，且连续失败轮数 `fail_streak >= 2`（`confirmed_dual_fail = True`）**，系统才会将该节点标记为 CDN 异常并触发热切！
- **抗“地区随机”节点污染与自动自愈（第 `3562~3619` 行）**：
  - 系统通过 `_is_random_region_node()` 自动识别名称中含有“随机/自动/轮询/负载均衡”等字样的节点，在排序时对其延迟乘以 **`1.28`（28% 延迟容差折算系数）**，使 `160ms` 的固定地区专线始终优先于 `145ms` 的随机轮询节点；
  - 更进一步，如果某个自动池当前排第一的节点是“地区随机”节点或 CDN 握手异常节点，系统会自动扫描本地节点库，挑选出延迟最优、状态 `ok` 且通过 CDN 校验的**固定地区专线节点**动态插入当前工作组首位完成自愈！

##### 5. 20 次滑动窗口质量评分（`compute_node_sliding_score`）与“只标记不强切”的新陈代谢
- **近期加权滑动评分算法（第 `1812` 行）**：
  每个节点在 `/etc/ai-link/node_probe.json` 中维护一个容量为 **20 次** 的探测历史环形窗口：
  - **成功率加权**：采用 **`40% × 全部20次成功率 + 60% × 最近5次成功率`**（既看长期稳定性，又对近期恢复或近期恶化保持高灵敏度）；
  - **延迟与抖动折算**：综合平均 RTT 延迟与变异系数 `CV = std / mean`（抖动率），计算出 `0 ~ 100` 的综合质量分，并授予 `S (≥90)`、`A (≥80)`、`B (≥70)`、`C (≥50)`、`D (<50)` 五级勋章。
- **“只标记、不强切”的温和淘汰机制**：
  - 只要节点当前 `state == "ok"` 且 `consecutive_fail == 0`，系统绝不会因为历史评分波动而强行切断您的连接；
  - 当某个节点连续 5 次评分低于 `50 分` 且落后所在分组平均分 `18 分` 以上时，节点旁会自动亮起醒目的 **`⚠️ 建议剔除`** 警告徽章，并提供 **`替换`** 按钮——点击后系统自动筛选出**同国家、尚未入池、健康可用且评分 ≥ 70 分**的优质备选节点，一键完成新陈代谢！

### 4.4 自动分流卡片（Shunt Cards）的三种绑定模式、自由排序与自定义规则用法

在 **`🎯 代理与分流`** 页面下半部分的 **“业务分流规则卡片区”**，AI-LINK 将复杂的路由表封装为一张张直观的业务卡片（如 `AI 智能服务`、`国际流媒体`、`YouTube`、`Netflix`、`Google 服务`、`GitHub 开发者`、`Telegram 通讯`、`游戏加速` 等，以及您自己创建的自定义分流卡片）。

#### 1. 分流卡片的三种出口绑定模式（怎么选最稳？）
点击任意一张分流卡片上的出口下拉框，您可以选择以下三类出口之一，**且所有三种模式均接入了后台 20 秒死节点自动逃生巡检**：

- **模式 A：绑定【🤖 自动节点池】（如 `AI自动`、`主力自动`）—— 旗舰推荐！**
  - **工作原理**：将该业务卡片直接交给您编排好的 1~5 组自动节点池托管。
  - **优势**：享受完整的 **1~5 组跨机房瀑布流容灾 + 双组去重探测 + 粘性不断不切 + 主力平滑回切**，是要求最高稳定性的业务（AI、办公、核心翻墙）的最佳拍档。
- **模式 B：绑定【🌍 国家/地区智能优选】（如 `🇭🇰 香港 · 自动优选`、`🇯🇵 日本 · 自动优选`、`🇺🇸 美国 · 自动优选`）—— 懒人福音！**
  - **工作原理**：无需手动建池，直接指定该业务走哪个国家/地区。后台由 `resolve_node_for_country_strategy_with_failover()` 自动筛选该地区所有 `state == "ok"` 且 `cdn_tls_ok == True` 的健康节点。
  - **永不断连保障**：一旦选定某个健康节点（如 `SG-N-2`），只要它后续保持 `ok`，系统就会一直粘性锁定在 `SG-N-2` 上绝不乱跳；而当 `SG-N-2` 发生故障（`delay == ERR` 或连续 2 次探测失败）时，后台 20 秒巡检看门狗（`_telemetry_and_watchdog_loop`）会自动将其热切至该国最快可用节点（如 `SG-N-4`），并在卡片分流链上点亮 **`⚡ 原出口不可用·已自动重选`** 提示徽章！
- **模式 C：绑定【📌 指定固定单节点】（如直接点选 `HK-BGP-IEPL-01`）—— 精准锁定 + 故障自动逃生！**
  - **解决传统插件“绑定单节点挂了就彻底断网”的痛点**：在传统插件中，如果您把卡片死绑到某个单节点，该节点挂掉后业务就彻底瘫痪。而在 AI-LINK 中，正常情况下 100% 严格走您指定的这个节点；但**一旦该节点彻底失联（`state != "ok"`），系统会自动触发同地区/全局健康节点临时逃生接管**，保证业务不断线，并在卡片上明确提示原节点异常已自动重选！
- **⚡ 2 秒无感热切换**：无论您在分流卡片上将出口从“日本”切到“美国”，还是从“自动池”切到“固定节点”，AI-LINK 均通过内核 Clash API 内存态热切完成，**约 2 秒即时生效，绝不重启 `sing-box` 内核，正在进行的下载与通话零中断**！

#### 2. 分流卡片自由排序（更改匹配优先级）
- **为什么卡片顺序很重要？** `sing-box` 路由引擎是从上往下按顺序匹配规则的。例如某个域名同时属于“微软服务”和“AI 智能服务”（如 `copilot.microsoft.com`），谁排在前面就会先命中谁的规则。
- **操作方法**：
  - 除了首尾两张锚定卡片（顶部的 **国内直连** 硬件护栏与最底部的 **全局兜底** 卡片）位置锁定外，**中间所有预设分流卡片与自定义分流卡片均支持自由排列**！
  - 直接点击卡片右上角的 **`↑ 上移`** 或 **`↓ 下移`** 按钮（或拖拽调整），即可实时改变该分流卡片在内核路由表中的匹配优先级。

#### 3. 组内编辑自定义分流规则 & 新建自定义分流卡片
- **在现有卡片内追加规则**：点击任意分流卡片上的 **`✏️ 编辑规则`**，即可直接向该卡片追加自定义域名后缀（如 `cursor.sh`、`claude.ai`）、域名关键字或 IP CIDR 段（一行一条），保存后自动编译进内核生效。
- **新建独立自定义分流卡片**：点击页面顶部的 **`+ 添加自定义分流规则`**，可创建全新的专属分流卡片（例如专门为某款海外游戏或公司内网创建一张卡片），并在 `<optgroup>` 分组策略中选择 **“🌐 走代理出口（限定节点地区 / 自动池 / 指定节点）”** 或 **“⚡ 特殊连接动作（直接出网 `direct` / 拦截丢弃 `block`）”**。
- **🔍 用分流路径追踪器一键验真**：配好卡片后，在底部的 **分流查询器** 中输入目标域名（如 `copilot.microsoft.com`），点击查询即可在 1 秒内看到完整的三阶路由沙盘：**① 命中的分流卡片名称与规则 -> ② 使用的 DNS 通道（`dns_fakeip` 或 `dns_direct`） -> ③ 当前实际出站节点与内核加载状态（`内核已加载该规则：是 ✓`）**。

### 5.7 连接与设置：硬件级国内旁路、IPv6 双栈与生命周期运维

![连接与设置：硬件旁路与IPv6双栈](ui_settings.png)

#### 页面核心功能详解：
1. **🚀 国内流量不进内核（硬件级旁路）**：
   - **核心作用**：开启后，国内域名走 `223.5.5.5` 解析，命中中国大陆 IP（`@cn_ip4` / `@cn_ip6`）的数据包在 `nftables` 防火墙层直接硬件放行，**完全不进入 `sing-box` 内核进程**，跑满宽带且 CPU 占用趋近于 0。
   - **单臂旁路由自动保护**：开启时自动挂载 `table inet ai_link` 的 `srcnat masquerade` 对称 NAT 与 `nf_conntrack_tcp_be_liberal=1` 护栏，确保单臂旁路由下国内 TCP 100% 不断流。
   - **分流冲突提示**：开启硬件旁路后，所有解析到大陆 IP 的站点均在防火墙层直接直连；若您希望强制让某个国内网站走海外代理，只需关闭此开关或为该域名添加一条 DNS 重写即可。
2. **🌐 IPv6 智能双栈架构与代理接管**：
   - **关闭时（默认推荐 · 智能双栈分流模式）**：国内域名（B站、PT、内网 NAS）正常返回真实 `AAAA` 走主路由原生 IPv6 满速直连；海外代理域名精准抑制 `AAAA` 并分配 IPv4 FakeIP，彻底杜绝旁路模式下海外流量从主路由 IPv6 抢答漏网。
   - **开启时（全量 IPv6 代理接管模式）**：启用 `fc00::/18` FakeIPv6 + `TProxy v6` 双栈透明代理与出站 `prefer_ipv4` 降级保护，支持访问纯 IPv6 海外站点并可点击 **`🩺 检测当前节点 IPv6 支持`** 巡检节点 IPv6 能力。
3. **🎛️ 插件运行管控、更新中心与加速源设置**：
   - 顶部提供三枚核心运维按钮：**`⏸️ 暂停透明代理（直连恢复）`**、**`⚡ 重启代理内核 (sing-box)`**、**`🔄 重启管理面板`**。
   - **🔒 冲突代理插件检查与自动隔离**：一键扫描并自动停止系统中可能残留的 `OpenClash`、`PassWall`、`HomeProxy`、`Nikki`、`SSR-Plus` 等冲突服务，防止多插件双写防火墙导致断网。
   - **🌍 GitHub 规则与核心更新加速源**：内置 `gh-proxy.com` 等多条国内高速镜像源，支持自定义镜像前缀，确保在国内网络环境下也能秒级更新 GeoIP/GeoSite 规则库与云端广告过滤列表。
4. **🔐 面板访问安全、配置备份恢复与一键恢复出厂**：
   - 支持设置管理面板访问密码（PBKDF2-SHA256 加密存储）与局域网免密/强制鉴权开关。
   - **📦 导出完整备份 / 📥 导入恢复配置**：一键导出或还原全部 17 项核心运行态配置（含面板密码哈希与 UCI 参数）。

### 6.3 零残留停止服务与彻底卸载

- **临时停止透明代理（保持安装）**：
  ```bash
  /etc/init.d/ai-link stop
  # 或使用命令行工具：
  ai-link stop
  ```
- **彻底卸载 AI-LINK 插件**：
  ```bash
  # 方式一：直接通过全局 CLI 卸载
  ai-link uninstall

  # 方式二：运行安装包内的卸载脚本
  sh /usr/share/ai-link/uninstall.sh
  ```
  卸载脚本会自动执行以下 6 步纯净回收：
  1. 停止 `sing-box` 与 `ai-link-daemon` 进程；
  2. 销毁 `nftables` 的 `table inet ai_link` 表，删除 `ip rule`（`fwmark 0x1 lookup 100`）与 IPv6 策略路由（含 `ip -6 route del fc00::/18 dev br-lan`）；
  3. 从 `/var/run/ai-link/sysctl_orig/be_liberal` 恢复内核 `net.netfilter.nf_conntrack_tcp_be_liberal` 的原始值；
  4. 清理 `/tmp/dnsmasq.d/ai-link*.conf` 并重启 `dnsmasq` 恢复默认 DNS；
  5. 清理 `/tmp/ai-link`、`/tmp/ai-link-run`、`/tmp/ai-link-cache` 等运行态文件（**不会误删 `/tmp/ai-link-openwrt` 安装源码目录**）；
  6. 移除 LuCI 视图缓存与启动项。

## 8. 使用须知与常见问题排查（FAQ）

1. **问：为什么自动节点池默认显示“🔒 不断不切”，此时组里有另一个节点延迟更低，为什么它不自动切过去？**
   - **答**：这正是 AI-LINK 实现 **“节点永不断连”** 的核心设计！频繁因为几毫秒的延迟差切换节点会导致您的公网出口 IP 改变，从而引起 ChatGPT 报错中断、游戏掉线、SSH 断开。只要当前正在工作的节点处于 `ok` 健康状态且 CDN 握手正常，系统会严格锁定该节点保持长连接不断开；只有当该节点真正故障掉线时，系统才会在毫秒间无缝切往组内或下一优先级组的存活节点。
2. **问：如果我发现自动节点池里的某个节点变慢了，或者出现了 `⚠️ 建议剔除` 提示，该怎么处理？**
   - **答**：系统通过 20 次滑动窗口评分自动监控每个节点的质量。当某个节点连续 5 次评分低于 50 分时，会点亮 `⚠️ 建议剔除`（为了不打断您正在进行的连接，系统默认只标记不强切）。您只需点击该节点旁边的 **`替换`** 按钮，系统会自动列出同国家、评分 `≥70分` 的优质池外节点供您一键平替。
3. **问：为什么我在分流页把百度/B站设为了走香港节点，但实际还是显示走国内直连？**
   - **答**：这是因为您在“连接与设置”中开启了 **“🚀 国内流量不进内核（硬件级旁路）”**。开启该开关后，所有解析为中国大陆 IP（`@cn_ip4` / `@cn_ip6`）的流量会在 `nftables` 防火墙层直接硬件放行，不再进入 `sing-box` 内核匹配分流规则。如果您确实需要让某个国内站点强制走海外代理，只需关闭“国内流量不进内核”开关，或在“DNS 与过滤”中为该域名配置一条重写规则即可。
4. **问：切换路由模式 vs. 切换某个分流卡片的出口节点，生效速度有什么区别？**
   - **答**：在分流卡片上直接切换出口节点（例如把“AI 智能”从日本切到美国，或更换自动节点池），系统通过 Clash API 热切换接口在 **约 2 秒内即时无感生效**，不会重启内核或断开现有连接；而切换顶层五大路由模式或修改底层自定义域名规则集时，系统会自动触发后台内核平滑重载（约 3~5 秒）。
5. **问：回家节点（HomeLink）创建后，手机在外面连不上怎么办？**
   - **答**：请依次确认三点：
     1. 家里宽带是否有公网 IPv4（或公网 IPv6），并在光猫/主路由上将回家节点的入站端口（如 `VLESS-Reality` 的 TCP 端口，或 `Hysteria2` 的 UDP 端口）映射到了安装 AI-LINK 的软路由 IP；
     2. 如果外网映射端口与内部监听端口不一致（例如外网端口 58443 映射到内网 8443），请在回家节点卡片编辑中填写“外网映射端口”，然后重新复制分享链接或扫码；
     3. 可在“回家节点 -> 回家隧道实时监控与接入明细”中查看节点是否显示为 `监听就绪`。
